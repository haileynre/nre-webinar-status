New: registrants in the first 5 minutes are dropped

⚠Fixing 322a alone won't cover this

322a only writes the WEBINARS row after its 5-minute wait, which gives Pulse time to claim webinars it made. 323e checks for that row the moment someone registers, and drops the registrant if it isn't there yet. The test registration came 64 seconds after the webinar was created, so it was dropped. It would have been dropped even with the IF node fixed.

Real webinars rarely get registrants that quickly, but every test like this one will, and so will any webinar someone shares right after creating it.

Still open after the 322a fix: the WEBINARS row still only appears after the 5-minute wait.

Proposed fix (needs approval): when 323e finds no row, it should hold the registrant and look again after the 5-minute window, rather than dropping them. For example, it could park them in the unmatched log and retry once the webinar's row lands.
