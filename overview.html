The eight systems (the whole migration)

The plan is not “rebuild every zap.” It is eight registry-driven systems plus a handful of small spokes. New campaigns become rows, not new workflows.

wave 1 · shadowing

1. Webinar funnels

Registration, date-tags, SMS. New events = registry rows. SMS is live in n8n. Zoom/WJ/AMA claim + sheets run in parallel; Zapier still does the customer-facing AC/Close work until a per-event flip.

wave 2 · built, not live

2. Lead routing

~1.05M tasks/90d of clones collapse into one hub + a 69-row table. This is the hot-app / SDR magnet / booking / Fast Pass pile. Explained below.

wave 3 · not started

3. Conversion tracking

Close/payment → PostHog, Google Ads, Hyros, Facebook. Planned as a Lambda, not n8n. ~200k tasks, 8 zaps we deliberately left out of Wave 2.

wave 4 · not started

4. Purchase intake

Stripe / ClickFunnels / WordPress → Close deal + AC + receipt. Money path. Shadow mandatory.

wave 4 · not started

5. Contract lifecycle

PandaDoc send-on-sale, signed-event fan-out, certificate PDFs. Includes Hailey KEEP auto-contract zaps.

wave 5 · not started

6. Student / MSA

Contract signed → trackers → welcome call → check-ins. ~37k tasks we pulled out of the lead-routing extract so they wouldn’t get eaten by accident.

wave 6 · not started

Close tags → Slack / Monday. Includes the #it-help KEEP.

wave 7 · last on purpose

8. AR / payment reminders

Delinquency stages, AR round robin, access revoke. Lowest volume, highest trust, so last.

Already live beside that plan: CYA (232b welcome + AC event router), phone verification (241c), Close/AC lead-ops spokes, and the webinar round-robin spoke (422a) that Wave 2 reuses rather than rebuilding.

How lead routing actually works

Today, Zapier has a clone per campaign: “Subto Fast Pass Typeform,” “HNWI opt-in,” “A–Z ebook,” “ZDB organic Typeform,” each doing the same job with slightly different tags and sheets. The n8n version is one pipeline with a lookup table.

The table is the product

LEAD_ROUTES is a 69-row n8n data table. Each row is a door:

  • what showed up — a Typeform id, an AC tag name, a list name, a webhook key, or a OnceHub calendar name
  • who it belongs to — brand (Subto / Gator / ZDB / TTTC) and pool (DOE or SDR)
  • what to do on cutover — AC tags to add, Slack channel, tracker sheet, whether to score the answers
  • the switch — cutover. Every live row is false. False means “remember we saw this, do not assign.” True means n8n does Close + round robin + Slack + the sheet, and that Zapier zap must be paused in the same minute.

69 rows today: 37 Typeform, 23 AC tags, 3 lists, 2 high-volume Subto webhooks, 4 OnceHub calendars. Zero cutover=true. 26 of them use the Hot App score model.

Example A — ZDB organic Typeform

Someone finishes form GtJHQFU4. Zapier still takes them to Close, round-robins a DOE, pings Slack, writes the tracker (~21k tasks/90d).

n8n already has that row. 232g would reshape the Typeform payload and call 423a. 232g is off, so nothing live hits the hub. A fake lead through 423a on this exact row claimed, skipped Close, and rejected the duplicate. That is shadow, working.

Example B — HNWI ebook tag

AC adds tag HNWI opt-in. 232b already sees every Subto tag. Zapier’s SDR zap still round-robins (~63k tasks/90d).

n8n has the row. The “known magnet tag? → 423a” path is sitting on 232b, disabled. Flipping that flag is a 232b save (~2 min AC webhook drop) and would shadow every matching magnet at once. Decision #309 is which door to open first.

Why 422a is not “the lead routing system”

422a is the picker: given a Close lead and DOE vs SDR, who is next. The webinar hub already uses it. Wave 2 does not rebuild it. The new work is everything around the picker: which door, which brand, whether to score, claiming, phone check, and the cutover writes. Calling 422a with a real lead during shadow would assign someone — that’s why it is behind the switch.

After the call (dispositions)

Separate system, same wave: when a DOE logs a completed / not-completed custom activity in Close, Zapier currently changes status and slaps DNC / Wrong Avatar tags. 424a/b are inactive drafts. The mapping table is empty because the Zapier clones still say NEED TO UPDATE on Close status ids. We are not inventing those.

What’s next (and what isn’t)

  1. Open a live shadow door for lead routing without pausing Zapier. Decision #309: extra Typeform webhook on ZDB organic (smallest blast radius), or connect 232b magnet tags (more volume, 2 min AC drop), or wait.
  2. Watch claims for 48h against Zapier task counts. Mismatch → stop.
  3. Per-route cutover, lowest volume first (ZDB organic, then TTTC KEEP). Flip the row and pause that zap in the same window. Rollback = flip the row back — but only if Zapier is still on, so write the runbook before the first true flip.
  4. Dispositions after sales-ops fills Close status ids.
  5. Wave 0 off-switch in the Zapier UI (200 zaps).
  6. Wave 1 per-event flips when Jason is ready (BiB last).
Will not happen until you say so: pause any live Zapier zap, set a LEAD_ROUTES row to cutover=true, connect 232b’s magnet path, or activate 232g/h/i. 423a being “on” only means other workflows can call it. Nothing inbound does.

Glossary

WordMeaning here
HubOne n8n workflow that does the job. Callers are thin.
SpokeA sub-workflow with no public webhook (score, round robin, phone check, Close upsert). Must be active or n8n refuses to run it.
Door / adapterThe thin workflow that catches Typeform / webhook / OnceHub / AC and calls the hub.
Shadown8n runs in parallel with Zapier, records the event, does not assign.
Cutovern8n assigns; that Zapier zap is paused.
DOE / SDRThe two round-robin pools. 422a only has these today (no Mastermind / Spanish pools unless a row needs them).
Hot appThe long Typeform application. Scored, then DOE round robin.
MagnetEbook / list / tag opt-in, usually SDR.
